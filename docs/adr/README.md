# Architecture Decision Records

ADRs capture durable technical or design decisions that future contributors and agents should not casually reverse.

## Status

Use:
- Proposed
- Accepted
- Superseded
- Deprecated

## Template

```md
# ADR XXXX: Title

Date: YYYY-MM-DD
Status: Accepted

## Context

What problem/constraint led to the decision?

## Decision

What was decided?

## Consequences

What becomes easier, harder, or constrained?

## Alternatives Considered

What meaningful alternatives were considered?
```

Do not create ADRs for trivial implementation details.
