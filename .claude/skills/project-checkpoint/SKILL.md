# Project Checkpoint

Use after a meaningful implementation or architecture change.

1. Inspect the actual diff and validation results.
2. Determine what is truly complete, in progress, blocked, and not implemented.
3. Update `docs/PROJECT_STATE.md`.
4. Update `docs/ROADMAP.md` only if sequencing or scope changed.
5. Create/update an ADR if a durable architecture decision changed.
6. Update `CHANGELOG.md` for a notable product/engineering milestone.
7. Never infer completion from filenames, TODOs, mocks, or planned code.
8. Record checks as PASS, FAIL, or NOT RUN with reasons.
